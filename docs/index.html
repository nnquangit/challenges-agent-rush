ProofBox

Overview

A containment-first control plane for AI agents: plan a task, run every step in a throw-away sandbox, and return a receipt anyone can verify.

Mock build. No container or VM runs, and the app makes no calls to Vultr or any other external service. Results such as "blocked", "OOM-killed" and "destroyed" come from software rules in MockSandbox; they are not evidence of real isolation.

What it is

ProofBox is built for the Vultr Agent Rush hackathon, Challenge 1 "Blast Radius Zero". Agents that run code or drive a browser can leak secrets or touch systems they should not. ProofBox puts a control plane between the agent and the machine: an LLM proposes a plan, the server validates and rewrites it, each step runs in its own sandbox that is destroyed afterwards, side effects wait for a human, and every step returns a receipt.

A receipt holds stdout/stderr, the exit code, artifacts, the environment the sandbox saw and an isolation report, all hashed with sha256 and signed with Ed25519. It can be checked in the browser or offline with a script.

Audience: hackathon judges and developers who want to know whether agent actions can be contained and audited.

Architecture

One Next.js app holds the UI and the API. Every request goes through the policy and the orchestrator before anything reaches a sandbox provider. Dashed boxes are mocks in this build.

  • UI src/components/ProofBoxApp.tsx starts a session (POST /api/session), calls the routes in src/app/api/* and polls the run.
  • Access src/lib/access.ts: every route except status, public key and session needs the pb_session cookie; its principal owns the plans and runs it creates. Local mode answers only loopback hosts.
  • Planner path: POST /api/chat → getLlm().plan() → enforcePolicy() → savePlan() (in memory, at most 200 entries, src/lib/store.ts).
  • Orchestrator src/lib/orchestrator.ts: walks the steps, up to 2 attempts for code steps, stops at awaiting_confirm before a gated step.
  • runInSandbox src/lib/sandbox/index.ts: takes a slot from the fair SlotPool (at most SANDBOX_MAX_CONCURRENT, 2 per principal, bounded queue), redacts the env, create → exec → artifacts → destroy() in finally, then seals the receipt.
  • Providers: getSandboxProvider() and getLlm() pick the mocks unless MOCK=0.
