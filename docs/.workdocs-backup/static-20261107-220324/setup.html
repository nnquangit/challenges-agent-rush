ProofBox

Setup

Install, configure, run, test and verify ProofBox locally in mock mode.

Mock build. No container or VM runs, and the app makes no calls to Vultr or any other external service. Results such as "blocked", "OOM-killed" and "destroyed" come from software rules in MockSandbox; they are not evidence of real isolation.

Prerequisites

  • Node.js and npm. No version is pinned: package.json has no engines field and there is no .nvmrc. The scripts use node --import tsx and --disable-warning, which need a recent Node; the checks for these pages ran on Node v24.18.0.
  • Dependencies (ranges from package.json, exact versions in the committed package-lock.json): next ^16.4.5, react ^19.3.1, react-dom ^19.3.1; dev: typescript ^5.9, tsx ^4.23.15, tailwindcss ^4.3.4, @tailwindcss/postcss ^4.3.4, @types/node ^22.
  • Accounts and services: none in mock mode. The Vultr variables in .env.example are for a later phase, and the providers that would use them are stubs.
  • Optional: python3 to serve these docs, curl for the API examples, a Chromium-based browser for in-browser Ed25519 verification.

Source: package.json, .env.example, README.md

Install

npm install

A package-lock.json is committed, so npm ci also gives a clean, locked install.

Source: README.md "Quick start", package-lock.json

Configuration

No configuration file is required; mock mode is the default. To change a limit, export the variable in the shell or copy .env.example to .env.local (Next.js reads it). Never commit real keys. Names and defaults come from src/lib/config.ts and src/lib/sandbox/signing.ts; integer variables fall back to the default when unset, not a number, or not positive.

Run

npm run dev                  # development server (next dev)
npm run build && npm start    # production build, then next start

Next.js serves on port 3000 by default, as the README states (http://localhost:3000); the project does not set another port. If 3000 is taken, pass a port and use that URL everywhere, for example npx next start -p 3117 -H 127.0.0.1. The checks for these pages used an existing production build with next start -p 3148 -H 127.0.0.1.

Source: package.json scripts, README.md "Quick start"

Verify the install

  1. Open the app URL. The header shows MOCK MODE · no Vultr calls.
  2. curl -s <app URL>/api/status returns "mode":"mock", "limits":{"timeoutMs":5000,"memoryMb":256}, the egress allowlist and "sandboxes":{"active":0,"queued":0,"max":3}.
  3. Click the preset Prove-It Python, then Dispatch to sandbox →. The chat ends with "Run succeeded: 3/3 steps succeeded" and the receipt badge reads CONTAINED (SIMULATED).
  4. In a receipt, click verify: "✓ sha256 recomputed in your browser · ✓ Ed25519 signature valid" appears.

All four were observed in Chromium on 2026-11-07.

Source: src/app/api/status/route.ts, src/components/ProofBoxApp.tsx, src/components/ReceiptViewer.tsx, src/components/IsolationBadge.tsx
