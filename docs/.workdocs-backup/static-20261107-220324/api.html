ProofBox

API

The eight HTTP routes, their shapes and errors, and the receipt verification CLI.

Mock build. No container or VM runs, and the app makes no calls to Vultr or any other external service. Results such as "blocked", "OOM-killed" and "destroyed" come from software rules in MockSandbox; they are not evidence of real isolation.

Interface type

HTTP + JSON through Next.js App Router route handlers in src/app/api/. There is no OpenAPI or GraphQL schema and no login. The only authentication is the optional x-proofbox-token header on /api/sandbox/exec. Every response sets cache-control: no-store (src/lib/http.ts). There is also a CLI, npm run verify-receipt (scripts/verify-receipt.mjs). In mock mode no endpoint calls Vultr.

Errors

Every error body is { "error": "<message>" } (src/lib/http.ts:bad).

CodeWhenRoutes
400Missing message or invalid JSON; wrong confirm body types; exec: no body, egressAllowlist present, bad kind or action (including submit), missing code/urlchat, confirm, exec
401Missing or wrong x-proofbox-token when PROOFBOX_DEMO_TOKEN is setexec
404unknown planId; run not foundruns, runs/:id
409Step not awaiting confirmation, unknown run, second decisionconfirm
413message or code over 20000 characters; files over 200000 characterschat, exec
429Rate limited (rate limited — retry in Ns) or all sandbox slots busyexec
502The planner's plan was rejected by policychat

Observed on 2026-11-07: invalid JSON → 400, unknown planId → 404, unknown run → 404, confirm on an unknown run → 409, empty confirm body → 400, exec with egressAllowlist → 400, exec with action: "submit" → 400. Not observed: 401, 413, 429 from slots, 502 (taken from the code).

Failures during a run return no HTTP error: the run becomes failed and the timeline says why (see How it works → Failure paths).

Source: src/lib/http.ts, src/app/api/*/route.ts

Try it

Start the app (Setup → Run), then:

BASE=http://localhost:3000   # change if the app runs on another port
curl -s $BASE/api/status

# metadata probe: the receipt has exitCode 1 and isolation.blockedAttempts is not empty (mock rules)
curl -s -X POST $BASE/api/sandbox/exec -H 'content-type: application/json' \
  -H "x-proofbox-token: $PROOFBOX_DEMO_TOKEN" \
  -d '{"kind":"browser","url":"http://169.254.169.254/"}'

# save a receipt and verify it offline
curl -s -X POST $BASE/api/sandbox/exec -H 'content-type: application/json' \
  -d '{"kind":"code","code":"print(6*7)"}' > receipt.json
npm run verify-receipt -- receipt.json --base $BASE   # two ✓ lines, exit 0

The token header is needed only when the server sets PROOFBOX_DEMO_TOKEN; never paste a real value into docs. verify-receipt also accepts the raw { "receipt": … } response, as above.
