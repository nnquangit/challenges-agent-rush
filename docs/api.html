ProofBox

API

The eight HTTP routes, their shapes and errors, and the receipt verification CLI.

Mock build. No container or VM runs, and the app makes no calls to Vultr or any other external service. Results such as "blocked", "OOM-killed" and "destroyed" come from software rules in MockSandbox; they are not evidence of real isolation.

Interface type

HTTP + JSON through Next.js App Router route handlers in src/app/api/. There is no OpenAPI or GraphQL schema and no user accounts. Callers are identified by a session principal: POST /api/session sets an HttpOnly, SameSite=Strict, HMAC-signed cookie pb_session, and every route except status, public key and session needs it. When PROOFBOX_DEMO_TOKEN is set, starting a session needs header x-proofbox-token; the token is not an identity. In local mode every route answers only loopback Host headers; cross-origin POSTs are refused. Every response sets cache-control: no-store (src/lib/http.ts). There is also a CLI, npm run verify-receipt (scripts/verify-receipt.mjs). In mock mode no endpoint calls Vultr.

Source: src/app/api/*/route.ts, src/lib/access.ts, src/lib/http.ts, package.json

Errors

Every error body is { "error": "<message>" } (src/lib/http.ts:bad); access errors add a code (src/lib/access.ts).

CodeWhenRoutes
400Missing message or invalid JSON; wrong confirm body types; exec: no body, egressAllowlist present, bad kind or action (including submit), missing code/urlchat, confirm, exec
401session_required: no valid pb_session cookie; token_required: missing or wrong x-proofbox-token on POST /api/sessionchat, runs, run, confirm, exec; session
403host_not_allowed: local mode and a non-loopback Host; bad_origin: a POST with a cross-origin Originall API routes
404unknown planId (missing or another session's); run not found (missing or another session's)runs, run, confirm
409Plan already dispatched; step not awaiting confirmation (second decision, replay)runs, confirm
413message or code over 20000 characters; files over 200000 characterschat, exec
429Rate limited (rate limited — retry in Ns); too many active runs; sandbox queue full or no slot within the wait; too many new sessionschat, runs, exec, session
502The planner's plan was rejected by policychat
503config_error: invalid security configuration (also stops the server at start)all API routes

Observed on 2026-11-07 with tests/adversarial.probe.mjs and tests/config.probe.mjs: 401 on every guarded route without a session (token set and unset), 401 for a missing or wrong token, 404 for another session's run, plan and confirm, 409 for a re-dispatch, a replayed approve and the second of two concurrent approves, 429 for a third active run and for a flooding session's excess execs, 403 for a foreign Host and a cross-origin POST. 503 and 502 are taken from the code.

Failures during a run return no HTTP error: the run becomes failed and the timeline says why (see How it works → Failure paths).

Try it

Start the app (Setup → Run), then:

BASE=http://localhost:3000   # change if the app runs on another port
curl -s $BASE/api/status

# start a session; keep its cookie in a jar (add -H "x-proofbox-token: $PROOFBOX_DEMO_TOKEN" if the server has a token)
curl -s -c jar -b jar -X POST $BASE/api/session -H 'content-type: application/json' -d '{}'

# metadata probe: the receipt has exitCode 1 and isolation.blockedAttempts is not empty (mock rules)
curl -s -b jar -X POST $BASE/api/sandbox/exec -H 'content-type: application/json' \
  -d '{"kind":"browser","url":"http://169.254.169.254/"}'

# save a receipt and verify it offline (pin the key you trust, or fetch it with --base)
curl -s -b jar -X POST $BASE/api/sandbox/exec -H 'content-type: application/json' \
  -d '{"kind":"code","code":"print(6*7)"}' > receipt.json
npm run verify-receipt -- receipt.json --base $BASE   # two ✓ lines, exit 0

Without the cookie every call but status, session and public key answers 401. Never paste a real token into docs. verify-receipt also accepts the raw { "receipt": … } response, as above; it has no default --base, and exits 3 (not 1) when the key cannot be fetched.
