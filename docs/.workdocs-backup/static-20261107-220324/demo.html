Demo script

A complete 3-minute demo of the mock build: setup, actions, narration, expected results, fallbacks and cleanup.

Mock build. No container or VM runs, and the app makes no calls to Vultr or any other external service. Results such as "blocked", "OOM-killed" and "destroyed" come from software rules in MockSandbox; they are not evidence of real isolation. Say this aloud during the demo.

Goal and audience

Show hackathon judges, in 3 minutes or less, that ProofBox keeps agent actions inside per-step sandboxes, puts a human in front of side effects, and hands back receipts anyone can verify. Challenge 1 asks for a visible containment moment (step 3).

Mode: mock. Every receipt shows CONTAINED (SIMULATED). Never present the mock as real isolation. When a Vultr sandbox exists, re-record steps 3 and 4 with a host terminal beside the browser.

Prerequisites

  • A laptop with Node.js and npm (Setup → Prerequisites), the project installed (npm install), two terminals, and a Chromium-based browser (in-browser Ed25519 verification needs WebCrypto Ed25519; otherwise use the CLI).
  • No accounts. No .env with real keys on the machine or on screen. Close private tabs, mail and chat.
  • Browser window about 1280×800 (the run below was checked at 1440×900). The app has a dark theme only.
  • An empty downloads folder: step 2 downloads receipt-<sandboxId>.json.
  • Optional: a screen recorder at 1080p with captions, or play the recorded video above.

Script

Seven steps. Each item gives the action (exact UI label or command), what to say, and what the audience should see. The diagram above the list walks through the steps on its own. Steps 2, 4 and 5 were run in Chromium against the current code on 2026-11-07 with the results shown.

  1. Open (0:00–0:20) — Action: show the title card, then the ProofBox home page. Say: "Agents that run code or drive a browser on your machine can leak secrets or touch production. ProofBox runs every step in its own throw-away sandbox and gives you a receipt you can check." Expected: presets in the Task panel; MOCK MODE · no Vultr calls in the header.
  2. Prove a claim (0:20–0:45) — Action: click the preset Prove-It Python (it plans at once), then Dispatch to sandbox →. Open step 1 and click verify, then download receipt.json. Say: "The claim, sum of primes below 100 is 1060, is checked in a sandbox step. In this mock build the sandbox is simulated: the code is matched against fixtures, not executed. The receipt is hashed and Ed25519-signed over everything, including the isolation report." Expected: chat "Run succeeded: 3/3 steps succeeded"; "✓ sha256 recomputed in your browser · ✓ Ed25519 signature valid" with "(ephemeral demo key)".
  3. Verify offline (0:45–0:55) — Action: in the second terminal run npm run verify-receipt -- ~/Downloads/receipt-*.json --base <app URL>. Say: "Anyone can re-check it offline." Expected: two ✓ lines (sha256, Ed25519), exit 0.
  4. Containment moment (0:55–1:35) — Action: open step 2 "Containment probe" (tag containment probe · policy), then step 3 "Resource cap probe". Point at the badge and the amber line under it. Say: "The server, not the model, adds this probe to every plan. It tries to read the API key, the host disk, cloud metadata and the Docker socket. All blocked. A 2 GB allocation is killed at the 256 MiB cap. In this build the sandbox is simulated; the policy rules and the receipt are real code." Expected: probe output shows [REDACTED] and "host filesystem: not mounted"; step 3 exit 137, killed by memory; badge CONTAINED (SIMULATED) and "Simulated by mock: no container or VM ran…".
  5. Self-repair (1:35–2:05) — Action: click the preset CSV Analyst, then Dispatch to sandbox →. Open the analysis step's attempts. Say: "The agent used the wrong column, saw the error, fixed it and retried in a new sandbox. Trying to POST the data out is blocked by the egress policy." Expected: attempt 1 exit 1 KeyError: 'revenue'; attempt 2 exit 0 with revenue_usd, a summary table and a bar chart; exfiltration probe blocked; "Run succeeded: 2/2 steps succeeded".
  6. Human gate (2:05–2:35) — Action: click the preset Research with Receipts, then Dispatch to sandbox →. When the dialog appears, click Deny. Then click Run again and, in the dialog, Approve submit. Say: "Browsing is limited to hosts you typed that are also on the server allowlist. Anything with a side effect waits for a human. Deny means it never runs. An approved submit in mock mode is captured by a fixture; nothing reaches a real site." Expected: evidence screenshot (Pro = $29 / month); metadata probe blocked; dialog "Human confirmation required" with focus on Deny; after Deny "Run succeeded: 4/5 steps succeeded" (submit skipped); after Approve "5/5".
  7. Close (2:35–3:00) — Action: show How it works and the threats table on Security, then the end card. Say: "Plan, dispatch, receipt. Planned on Vultr: Serverless Inference for the LLM calls and Docker with gVisor on a Vultr VM for the sandbox. ProofBox: blast radius zero, with receipts." Say "running on Vultr" only once it is. Expected: the static docs pages; the repository and demo URL on the end card only when they exist.

Fallbacks

FailureWhat to do live
Server does not start, or port 3000 is busyStart on another port (npx next start -p 3117 -H 127.0.0.1) and use that URL; keep a pre-recorded clip of steps 2–6 ready
A run stays on "Running…"All 3 slots may be busy from earlier runs; wait a few seconds (mock runs drain quickly), or restart the server (receipts signed before the restart no longer verify with an ephemeral key)
A step fails unexpectedlySay it is a mock run, switch to another preset, continue with the next step
verify in the browser shows no signature resultThe browser lacks WebCrypto Ed25519; use the CLI command from step 3
CLI warns about a keyId mismatch or cannot connectWrong --base, or the server restarted; pass the correct app URL, or skip to the in-browser check
Running out of timeDrop step 5; keep steps 4 and 6 (containment moment and human gate)

Cleanup

  1. Stop the server you started with kill <PID>, only that PID. Do not kill by name: other services may run on the machine.
  2. Delete the downloaded receipt-*.json files.
  3. Close the browser tabs and the recorder; check the recording for any key, email address or token in frame.
  4. Runs live in memory only, so stopping the server clears them.
